# Day 8 — Course Reflection

The most difficult concept in this course was designing systems that remain correct under heavy traffic, especially when multiple users attempt to modify the same data simultaneously. I learned that having a fast application is not enough if it can produce incorrect results. TicketHub helped me understand how database transactions, row-level locking, unique constraints, and idempotency work together to prevent double-booking. I overcame this challenge by breaking the booking process into smaller steps and examining what could happen when two users try to reserve the same seat at the same time.

Based on the feedback and requirements I encountered during my capstone work, I would improve my project documentation, repository organization, and testing. I would verify that every required file is present in the correct directory, that the implementation matches the assignment rubric, and that important edge cases are tested before submission. I would also improve error handling and test how the application behaves when an API request fails, a page reloads, or a user submits the same request more than once. These improvements would make my work more reliable and easier for another developer to understand.

Next, I want to learn more about cloud deployment, automated testing, and performance testing. I would like to deploy a complete application, use tools to simulate thousands of concurrent users, and monitor its response times and failures. I also plan to strengthen my knowledge of SQL transactions, database indexing, and backend security. My goal is to become a data scientist and software developer who can build systems that are not only functional but also scalable, secure, and dependable in real-world conditions.
